# Tree 検索の改良計画

作成日: 2026-11-22
対象: [app/agent.py](../app/agent.py) の `--tree`、[app/retrieval.py](../app/retrieval.py) の `browse_tree`、[app/tools.py](../app/tools.py) の `browse_tree`
範囲: Tree だけを改修する。Graph（`--graph` / `search_graph`）は今回扱わない。

## 方針

1. 現状の `--tree` ではうまくいかない質問を実行し、失敗を記録する（済み: Q1）。
2. 失敗の原因に合わせて、「根拠として挙がったページを全文で読み、回答に使う」ように直す。読んだページ以外の引用はコードで検証して差し戻す。ただし検証できるのは「引用が全文を読んだページか」までで、本文が主張を裏付けているかは人が確認する。
3. 同じ質問で前後を比べる。

## 1. 現状

- データ: tree.json（講義 → 章 → ページ）。本文は lectures.json から引く。
  対象は第1〜3回の本講義で、全部で214ページ。
- 検索の流れ: モデルが `browse_tree` を1階層ずつ呼んでたどる。
  1. 引数なし → 講義一覧
  2. 講義ID → 章の一覧
  3. 章ID → ページの一覧
  4. ページID → 全文
- 子ノードがページのときは、本文の先頭1文だけを返す。指定したページ自身は全文を返す。
- 第2回と第3回では、章に入らないページ（表紙、アジェンダなど）が講義の直下に並んでいる。第2回は5件、第3回は4件。
- 呼び出しのたびに tree.json と lectures.json を読み直している。

## 2. 現状でうまくいかない質問

| # | 質問 | 結果（2026-11-22） |
| --- | --- | --- |
| Q1 | 第1〜3回のそれぞれで「評価」はどう扱われている？ | 失敗: lec01〜03 の目次は開いたが、どのページの全文も読まずに回答した（参考: `--graph` では lec01・02・03 をそれぞれ読んで回答した） |

失敗の原因（トレース: [lectures/05/answer.md](../lectures/05/answer.md)。入力 10,838 tokens、モデル応答6回）:
呼び出しの流れ: 講義一覧 → lec01 → lec02 → lec03（ここまでは章名の一覧）→ lec01 の章「AIエンジニアリングの基礎」（ページ一覧と先頭1文）→ 回答。

| 回 | どこまで開いたか | 回答での扱い |
| --- | --- | --- |
| lec01 | 1つの章のページ一覧（先頭1文のみ） | ページ番号を付けて回答。ただし本文の全文は読んでいない |
| lec02 | 章名の一覧だけ | 章名から推測して書いている。引用なし |
| lec03 | 章名の一覧だけ | 「PDF p.42」「p.49」と引用しているが、これは章ID（`s042`・`s049`）の数字。ページの根拠ではない |

- **主な原因は、探索はしたが、根拠になる本文を読まずに回答したこと。**
  - lec02・lec03 は章名の一覧まで開いたが、章の中にもページにも進んでいない。
  - 全文を返すのは「ページIDを指定したとき」だけで、Q1 では一度もページIDを指定していない。
- その結果:
  - 章名や先頭1文から推測して書いた。
  - 章IDの数字をページ番号として引用した（引用を作ってしまった）。
- その背景:
  - 章の一覧には章名しかない。どの章に「評価」の本文があるか判断できないので、どの章を開くかを決められない。
  - 指示文には「全文を読んでから回答する」「見出しだけで答えず」がすでにある（[app/agent.py](../app/agent.py) の `TREE_INSTRUCTIONS`）。指示はあったが、守られなかった。
  - ツールの返り値では、候補（先頭1文だけ）と根拠（全文）の区別がつかない。回答の引用が読んだページかどうかを照合する仕組みもない。そのため、モデルからは章名もページ番号も同じ「根拠」に見える。
  - ID の形（`lec03-main-s042`）が PDF のページ番号に見えてしまう。

## 3. 何を直すか

いまの `TREE_INSTRUCTIONS` にも、すでに次の2行がある。

- 「関係するページIDで browse_tree を呼び、nodeの全文を読んでから回答する」
- 「見出しだけで答えず」

それでも Q1 では守られなかった。指示文を足すだけでは足りないので、次の方針で直す。

- どこまでたどるかは、データ（講義 → 章 → ページ）の形で決まる。探索の深さ（depth）は指定しない。探索の手順もモデルに任せる。
- 直すのは「回答に使ってよいページ」の扱いである。
  - 全文を読んだページを記録する。
  - 回答の引用がそのページかどうかを、コードで検証する。
  - 読んでいないページを引用していたら、差し戻して読ませる。

## 4. 改良内容

### 4.1 読んだページを記録する（データの持ち方）

- 1回の実行ごとに、次の2つを記録する。
  - `listed`: 一覧に候補として出たページ（page_id → 第N回・PDF p.N）
  - `read`: 全文を返したページ（同じ形）
- 記録は Pydantic AI の `deps`（実行ごとに渡すデータ）に持たせる。
  - 理由: 実行ごとに分かれるので、別の質問と混ざらない。グローバル変数にしないので、テストもしやすい。
- `--tree` 専用のエージェントを作る: `tree_agent = Agent(instructions=TREE_INSTRUCTIONS, deps_type=TreeDeps, retries={'output': 2})`。
  - 理由: 既存の `agent` は、通常モード・`--graph`・`--full-context`・`--mcp`・tests/test_agent.py で共有されている。`@agent.output_validator` は `override()` で差し替えられないので、既存の `agent` に登録すると他のモードにも検証がかかってしまう。
  - `--tree` のときだけ `target = tree_agent` とする。いまの `agent.override(instructions=TREE_INSTRUCTIONS, tools=[tools.browse_tree])` は削除する。
- tree 用のツールは `RunContext[TreeDeps]` を受け取る関数にして、`Tool(..., takes_ctx=True, name="browse_tree")` で `tree_agent` に登録する。
  - ツール名は `browse_tree` のままにする。`print_trace` の `part.tool_name == "browse_tree"` の分岐や、指示文と合わせるため。
  - 中身は既存の `retrieval.browse_tree` を呼び、記録と 4.2 の項目を足すだけ。
  - 既存の `tools.browse_tree`（MCP でも使う）は変えない。
- tree.json・lectures.json は変更しない。新しいデータファイルも作らない。

### 4.2 候補の返し方

- 一覧に出るページ候補に、次を付ける。
  - `"read": false`（まだ全文を読んでいない）
  - `"cite_after_read": "第N回・PDF p.N"`（読めば引用できる形）
  - 理由: モデルが候補を根拠として扱う前に、「まだ読んでいない」ことが返り値でわかるようにする。
- 全文を返したときは `"read": true` と `"cite": "第N回・PDF p.N"` を付ける。
  - 引用の書き方をツールが返すので、章ID（`s042`）の数字をページ番号と取り違えなくなる。
- 章ノードは、いまと同じく `page` を持たない。
- 子ノードの並びは、tree.json の元の順序のまま変えない。並べ替えや「その他」へのまとめはしない（章の中の順番を問う質問で、元の順序が手がかりになるため）。

### 4.3 回答を検証する（`output_validator`）

Pydantic AI の `@agent.output_validator` で、最終回答を返す前に検証する。失敗したら `ModelRetry` で理由を返す。モデルはツール呼び出しを再開してから、答え直す。

検証の内容:

1. **引用がすべて読んだページか。**
   - 回答から「第N回 … PDF p.X」の引用を取り出し、1ページずつ展開する。次の表記揺れを許す。
     | 揺れ | 例 |
     | --- | --- |
     | 回と PDF の間の区切り | `第1回・PDF p.34`、`第1回 PDF p.34`、`第1回、PDF p.34` |
     | 列挙の区切り | `,`、`、`、`/`、空白（`p.34, p.52`、`p.34、p.35`） |
     | 2つ目以降の `p.` の省略 | `p.34, 35` |
     | 範囲の記号 | `-`、`–`、`〜`、`~`（`p.34〜35`） |
     | 全角数字 | `ｐ.３４`（NFKC 正規化してから取り出す） |
   - 取り出し方: NFKC 正規化 → `第(\d+)回` の直後（間は空白・`・`・`、` のみ）にある `PDF\s*p\.` から、数字・区切り・範囲記号が続くところまでを1つの引用とみなし、数字を展開する。
   - 書き方を固定するため、指示文では「`cite` の書き方をそのまま使う」と指定する。
   - 1つでも `read` にないページがあれば差し戻す。
   - 差し戻しの文には、そのページのIDを書く（例: 「第1回・PDF p.35 は全文を読んでいません。browse_tree("lec01-main-p035") で読んでから答えてください」）。
   - ページIDは、対象資料の全ページ（`load_pages()`、214ページ）から 第N回・PDF p.N で引く。`listed` は使わない（一覧に出ていなくても、資料にあるページはある）。
   - 全ページにも無い番号のときだけ、「第1〜3回の資料にないページ番号です」と返す。
2. **質問で求めた回と回答で触れた回のそれぞれに、根拠があるか。**
   - 対象の回 = 質問から取り出した回 ∪ 回答に出てくる回。
     - 質問からは「第N回」「第N〜M回」「第N・M回」を取り出す（例: Q1「第1〜3回のそれぞれ」→ 1・2・3）。
     - 回の指定がない質問では、回答に出てくる回だけを対象にする。
   - 対象の各回について、読んだページの引用が1つもなければ差し戻す。回答から抜け落ちた回も、ここで検出する。
   - ただし、その回について「確認できない」と書いているなら通す（全文を読んでも根拠がなかった場合）。
   - 「その回について」の判定方法: 回答を「第N回」が出てくる位置で区切る。区切りは、ある「第N回」から、別の回の「第M回」（M≠N）が出てくる直前まで。第N回の区切りのどれかに「確認できない」があれば、第N回は通す。
     - 回答全体に「確認できない」があるかどうかでは判定しない。第3回の「確認できない」で、第2回の抜けまで通ってしまうため。
     - 引用は「第N回・PDF p.X」の形で回を自分で示すので、区切りに関係なく、その回の引用として数える。
   - 例: Q1 で第2回を引用なしで説明した、という失敗をここで止める。

差し戻しは最大2回（`retries={'output': 2}`。pydantic-ai 2.57 には `output_retries` 引数がなく、`retries` の `output` で指定する）。それでも通らなければ、エラーとして終了する。根拠のない回答は出さない。

- 上限を超えると、`run_sync()` は result を返さずに `UnexpectedModelBehavior` を送出する。いまの agent.py は result が返ってから `print_trace(result)` を呼ぶので、このままではトレースが出ない。
- そこで `with capture_run_messages() as messages:` の中で実行し、`UnexpectedModelBehavior` を捕まえる。捕まえたら次を表示して、`SystemExit(1)` で終わる。
  - 最後の差し戻し理由
  - `messages` から組み立てたトレース
  - `deps.read`（全文を読んだページ）
- `print_trace` は、result ではなく「メッセージの一覧と usage」を受け取る形に分ける。失敗時は usage が取れないので、使用量の行は省く。

### 4.4 指示文（`TREE_INSTRUCTIONS`）

- 「引用してよいのは、browse_tree で全文を読んだページ（`read: true`）だけ。引用は返された `cite` の書き方にする」を足す。
- 「回答は検証され、読んでいないページの引用は差し戻される」と書く。
- 既存の「全文を読んでから回答する」の行は残す。

### 4.5 トレース表示

- `print_trace` で、次を表示する。
  - 差し戻し（`RetryPromptPart`）の理由
  - 最後に `read`（全文を読んだページ）の一覧を回ごとに
- 評価の表を、トレースからそのまま埋められるようにするため。

## 5. 実装手順・テスト・評価

1. `deps` 用のクラスと、記録付きの tree ツールを作る。
2. 引用の取り出しと検証を、関数として作る（`output_validator` から呼ぶ）。
3. `--tree` のときに、`deps`・ツール・検証を使うよう agent.py を変える。
4. `TREE_INSTRUCTIONS` と `print_trace` を更新し、`UnexpectedModelBehavior` を捕まえる処理を足す。
5. テスト（APIは呼ばない）:
   - ページIDで開くと `read` に入り、一覧に出ただけでは `listed` にしか入らない
   - 一覧の候補に `read: false` と `cite_after_read` が、全文には `read: true` と `cite` が付く
   - 引用の取り出し: 「第1回・PDF p.34-35, p.52」から (1,34)(1,35)(1,52) を得る
   - 表記揺れ: 「第1回・PDF p.34、p.35」「第1回・PDF p.34, 35」「第1回 PDF p.34」「第1回・PDF p.34〜35」がどれも取り出せる
   - 「第3回については確認できない」とだけ書き、第2回の引用がない回答は、第2回の抜けで `ModelRetry` になる
   - 通常モードの `agent` には検証がかからない（tests/test_agent.py が今までどおり通る）
   - 差し戻しの上限を超えると、`SystemExit(1)` で終わり、トレースと `read` が表示される
   - 読んでいないページの引用で `ModelRetry` になり、文にページIDが入る
   - 回答に第2回が出てくるのに引用がなければ `ModelRetry` になる。「確認できない」と書いてあれば通る
   - 質問が「第1〜3回」で、回答が第1回と第3回だけを引用しているなら、第2回の抜けで `ModelRetry` になる
   - 一覧に出ていないが資料にあるページの引用は、そのページIDを示して差し戻す。資料にない番号は「資料にない」と返す
   - 質問から回を取り出す: 「第1〜3回」→ {1,2,3}、「第2・3回」→ {2,3}、指定なし → 空
   - 全部読んだページなら通る
   - TestModel を使い、差し戻し → 再読 → 合格の流れが一周する
6. 評価: Q1 を、同じモデル・同じ対象資料で、次の3通りで実行して比べる（[lectures/05/problem.md](../lectures/05/problem.md) の発展4・5に合わせる）。
   - 基本RAG（引数なし、`search_materials`）
   - `--tree` の改修前
   - `--tree` の改修後
   結果はこの表から [lectures/05/answer.md](../lectures/05/answer.md) に転記する。

- 引用したページの本文が主張を裏付けているかは、人が確認する。
